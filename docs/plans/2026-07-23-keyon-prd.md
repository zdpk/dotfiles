# keyon product requirements

## Status

- Product: `keyon`
- Platform: macOS
- Document date: 2026-07-23
- Product behavior: Approved
- Implementation status: Not started
- CoreHID status: Development entitlement request drafted; submission pending

## Product summary

keyon is a small macOS utility that makes multilingual keyboard switching easy
without requiring users to understand Karabiner-Elements, Hammerspoon, F18/F19
remapping, or macOS input-source shortcut internals.

The entire product is one simple settings window:

- Right Command toggles a user-selected primary language pair.
- Option+1, Option+2, and Option+3 switch directly to optional
  user-selected languages.
- Any optional slot may remain empty.
- A keyboard-shaped visual shows exactly what each shortcut does.

## User problem

Korean and Japanese users frequently alternate between Roman-alphabet input and
local input methods. macOS provides input-source shortcuts, but configuring a
convenient dedicated language key on a standard keyboard is difficult for
non-technical users.

The existing advanced-user workflow typically combines a remapping utility,
unused function keys, macOS keyboard shortcuts, permissions, and background
components. keyon replaces that multi-step configuration with a direct visual
mapping.

## Primary user experience

The window should feel like setting labels on a small keyboard, not configuring
a keyboard driver.

```text

│  주 언어                                                      │
│  [ English                 ]  ⇄  [ 한국어                    ] │
│                                      [ right command  ⌘ ]     │
│                                                               │
│  빠른 언어                                                    │
│  [ ⌥ + 1   日本語        ▾ ]                                  │
│  [ ⌥ + 2   中文          ▾ ]                                  │

│                                                               │
│  ┌───┬───┬───┬───────────────────────────────┬─────────────┐  │
│  │ 1 │ 2 │ 3 │                               │ right ⌘     │  │
│  └─⌥─┴─⌥─┴─⌥─┴───────────────────────────────┴── 언어 전환 ─┘  │
```

The production UI may use a simplified keyboard illustration rather than this
literal layout. The important requirement is that the shortcut-to-language
relationship is visible without reading documentation.

## Functional requirements

### Primary language pair

The user selects two distinct enabled macOS input sources:

- Primary 1
- Primary 2

Right Command follows a fixed, stateless rule:

```text
current source = Primary 1  -> switch to Primary 2
current source = Primary 2  -> switch to Primary 1
current source = anything else or unknown -> switch to Primary 1
```

keyon never remembers the last primary language. Optional languages never enter
the Right Command cycle.

If ABC and Korean 2-Set are enabled, the first-run suggestion is:

```text
Primary 1: Korean 2-Set
Primary 2: ABC
```

The user may replace either source with any enabled input source.

### Optional language slots

keyon provides three optional direct-selection slots:

- Option+1
- Option+2
- Option+3

Each slot accepts any enabled macOS input source or `Not Set`.

- A configured shortcut selects its source directly.
- Pressing it again while already selected is harmless.
- An unconfigured shortcut is not captured and retains normal macOS behavior.
- A source removed from macOS becomes unavailable; keyon does not silently
  substitute another source.
- Either physical Option key may invoke a configured slot.
- Pressing Option without a number remains a normal modifier action.

### Settings behavior

- The language picker lists currently enabled macOS input sources.
- Missing languages are added through a single `Open Keyboard Settings` action.
- Changes save and apply immediately.
- No separate Save or Apply button is required.
- The window shows whether keyon is active.
- The app can start automatically at login.
- Left Command remains a normal Command modifier.
- Right Command is dedicated to the primary-language action and does not invoke
  Command shortcuts.

## First-run flow

1. Open keyon.
2. Select Primary 1 and Primary 2.
3. Optionally assign languages to Option+1, Option+2, and Option+3.
4. Enable login launch if desired.
5. Close the window and use the shortcuts.

The flow should take less than one minute when the input sources are already
enabled.

## State

keyon persists only configuration:

- Primary 1 source ID
- Primary 2 source ID
- Optional slot 1 source ID or empty
- Optional slot 2 source ID or empty
- Optional slot 3 source ID or empty
- Login-launch preference
- Enabled state

keyon does not persist:

- Last active primary language
- Language history
- Typed text
- Per-application state

## Technical boundaries

The product contract supports any enabled macOS input source, but Virtual HID
does not encode arbitrary macOS input-source IDs.

- CoreHID is used only to reproduce native language-key events for which a
  standard HID input-method usage exists, initially Korean and Japanese.
- Korean and Japanese virtual devices use the appropriate keyboard
  localization and narrowly scoped language reports such as LANG1 or LANG4.
- Arbitrary configured input sources require the macOS input-source API.
- The app selects the backend internally. Users should not need to understand
  this distinction.
- The virtual-device descriptor must not expose ordinary alphanumeric typing,
  pointer events, or arbitrary shortcut injection.

Right Command capture and Virtual HID output are separate responsibilities.
The current prototype's `hidutil` to F18 mapping and Carbon registered-hotkey
path may be retained behind the app, so users do not need to install a separate
remapper.

The initial CoreHID backend cannot be validated end to end until Apple grants
`com.apple.developer.hid.virtual.device` and a matching development provisioning
profile is used to sign the app.

## Error handling

- If a configured source is disabled or removed, mark it as unavailable and
  stop capturing its shortcut.
- If Primary 1 or Primary 2 is unavailable, disable Right Command switching and
  show one clear recovery action.
- If another remapper owns Right Command, show a conflict message instead of
  applying competing mappings.
- Do not report a successful source change until macOS readback matches the
  requested source.
- CoreHID initialization failure must identify entitlement, profile, signing,
  and permission failures separately.

## Privacy and security

- No key logging
- No typed-text storage or analysis
- No network transmission
- No arbitrary macro or scripting interface
- No general-purpose virtual keyboard
- All configuration stored locally
- Generated language actions occur only after an explicit configured shortcut

## Non-goals

- General keyboard remapping
- Macro automation
- Per-application language profiles
- Language usage history
- Cloud synchronization
- Editing or installing macOS input sources
- Replacing normal left-side modifier keys
- Remembering the last language used before an optional language

## Acceptance criteria

- Right Command switches only between the configured primary pair.
- From any third or unknown source, Right Command selects Primary 1.
- Right Command behavior is independent of previous history.
- Each configured Option+number shortcut selects the assigned source directly.
- Each unconfigured Option+number shortcut passes through normally.
- Bare Option remains a normal modifier.
- The complete configuration is understandable from one keyboard-shaped
  settings window.
- No separate Karabiner-Elements or Hammerspoon installation is required.
- Configuration persists across logout and restart.
- The app clearly reports missing sources, shortcut conflicts, and unavailable
  Virtual HID permission.
- Korean/English and Japanese switching are verified in TextEdit, Safari,
  terminal applications, Codex, and secure-input fields.
