# Native 한/영 설정의 반복 적용

사용자는 Caps Lock과 별도 전환 앱을 사용하지 않는
우측 Command → F18 → macOS 기본 입력 소스 전환 구성을 선택했다.
빠른 WebKit 입력에서 이미 확인된 오류를 해결했다고 간주하지 않는다.
이번 변경의 합격 기준은 설정의 설치·재적용·복구와 로그인 매핑이다.

## 적용 경로

`make input-sources`와 macOS bootstrap은 기본적으로 `native` 백엔드를 선택한다.
`script/native-input.sh`가 macOS 기본 `osascript`로 `scripts/macos/native-input.js`를
한 번 실행한다. JavaScript for Automation의 Carbon bridge는 설치할 때에만
입력 소스를 정리한다. 키를 누를 때 실행되는 코드가 아니다.

- ABC와 두벌식 한글만 활성화한다. 다른 keyboard source와 일본어는 제외한다.
- 우측 Command를 F18로 매핑한다. Caps Lock 매핑·전환 옵션은 변경하지 않는다.
- 기본 입력 소스 단축키 60은 끄고, 61은 F18로 설정한다.
- 기존 dotfiles 전환기와 해당 HID LaunchAgent를 중지하고 교체한다.
- 지원하는 Karabiner 사용자 core는 공식 unregister 명령으로 중지한다.
- 새 로그인 LaunchAgent는 내장 hidutil을 한 번 실행하고 종료한다.
- `input-backend=native`, `input-mode=ko-en`은 노드의 홈에 저장한다.

Caps Lock 중계는 사용자가 제외했다. 기존 Swift 백엔드는 명시적인
`BACKEND=helper`에서만 선택한다. 기본 기능으로 한/영만 순환하려면 일본어를
같은 활성 입력 소스 목록에 두지 않는다. 예전 노드별 일본어 설정은 최초 백업에 보존한다.

## 실패와 복구

상태는 공유 checkout 밖의 `~/.local/state/dotfiles/native-input/`에 기록한다.
최초 백업을 유지하고 프로세스 잠금으로 동시 적용을 차단한다.
적용 중 오류가 나면 해당 실행 전 상태로 되돌린다. 재적용 실패가 최초 백업을
덮어쓰지 않는다. 복구가 끝나지 않으면 기록을 유지하고 새 적용을 차단한다.

복구는 대상 단축키 60/61만 현재 단축키 사전에 병합한다. 관련 없는 단축키를
설치 이후 사용자가 바꾸었더라도 덮어쓰지 않는다. 기존 Caps Lock 등 다른 HID
매핑은 보존한다. 이전 구현의 우측 Option → F19 매핑만 제거한다.
써드파티 입력기를 다시 활성화할 때 macOS 승인이 필요하면 다른 복구 단계를
진행한 뒤 실패를 보고한다. 시스템 승인을 마치고 restore를 재실행할 수 있다.

## 검증

자동 테스트는 실제 키 입력을 하지 않는다. 최초 설치, 재적용의 무변경 처리,
원래 일본어 프로필 복구, 부분 실패, 복구 실패 후 재진입 차단, 설정 읽기 불일치,
관련 없는 매핑·단축키 보존, native/helper 모드 선택을 검사한다.
실제 JXA/Carbon/launchd 통합은 사용 중인 m1이 아닌 m5에서 확인한다.

설정 읽기 검사와 실입력 합격은 분리한다. 이번 작업은 빠른 전환의 문자 보존,
모든 앱, 모든 상태바 프레임의 일치를 새로 보증하지 않는다.

### 2026-09-14 확인 결과

- native 설정 테스트 11개와 기존 테스트 전체가 통과했다.
- 커밋 대상 파일만 추출한 별도 디렉터리에서도 `make test`가 통과했다.
- m5에서 실제 적용과 모든 설정 읽기 검사가 통과했다.
- 반복 적용은 최초 백업을 보존하고 전환 서비스를 재시작하지 않았다.
- 복구 후 원래 입력 소스·선택·단축키·서비스·노드 설정을 확인했다.
  이전 Fcitx 활성화를 위한 macOS 승인 단계가 필요했다.
- m5의 매핑을 잠시 제거한 뒤 설치된 로그인 작업을 실행해 복원을 확인했다.
  실제 재부팅을 수행한 시험은 아니다.
- m5에서 일본어·Dvorak 추가 후 정리, 일본어·Fcitx 동시 활성 상태의 적용도 통과했다.
- m1(macOS 26.6.2)은 API로 제거되지 않은 Fcitx 때문에 적용을 거부하고 자동 복구했다.
  이전 구성을 `native-input/before-fcitx-ui-removal-20260914-002738.json`에 보존하고,
  시스템 설정에서 Fcitx 항목을 한 번 제거한 뒤 적용이 통과했다.
  m1 시스템 설정 화면에도 ABC와 두벌식 한글만 남은 것을 확인했다.
  native restore의 백업은 이 Fcitx 정리 이후, native 적용 직전 상태를 기준으로 한다.

설치 소스 목록과 실제 활성 목록은 구분한다. 비활성 IME의 입력 모드도 내부
IsEnabled 값이 true일 수 있으므로 `TISCreateInputSourceList`의 활성 목록을
기준으로 삼는다. 설치 단계의 변경·조회는 각각 별도 단기 osascript 프로세스에서
실행해 같은 클라이언트의 캐시를 재사용하지 않는다. 한 번에 여러 입력 소스를
바꾸지 않고 각 소스의 활성화·비활성화를 별도 호출한다. 그래도 잔여 입력 소스가
관측되면 검증을 생략하지 않고 적용을 실패시킨다. 이 프로세스들은 키 입력을 처리하지 않는다.
